# ADR 0006：manager 制定任务管线，验收执行委派给 worker

状态：已在 2026-11-03 被 ADR 0010 取代；链表自动推进不再是 manager 产品接口。

- 日期：2026-11-02
- 状态：已接受
- 依据：用户第三轮答复：“验收也委派出去”，manager 可在委派任务时制定任务管线，例如 A 实现、B 对抗性验收。
- 更新：ADR 0004 中由 manager 直接执行验收测试的职责分配。

## 决定

manager 负责理解和传达需求、制定任务管线及各阶段要求、委派任务、处理阻塞并对用户汇报。验收的具体执行也委派给 worker。

用户给出的管线示例是：worker A 根据 manager 传达的需求实现；worker B 根据 manager 制定的要求进行对抗性验收。实现与验收可以分配给不同 worker 实例；用户尚未要求它们必须采用不同 CLI 或模型。

第四轮进一步确认：管线采用链表式，阶段顺序执行；简单任务甚至可以不注册验收。首版不以通用依赖图或固定两阶段流程作为需求。

对抗性验收失败时，验收 worker 提供证据，manager 安排实现 worker 返工，再由验收 worker 复验；循环上限由 manager 管理。

manager 应尽可能待命。消息入口提供普通发送和立即打断两种方式，由用户选择；普通发送可在 manager 忙碌时等待，不强制打断。

第五轮进一步确认：中央服务自动推进已注册的下一阶段，管线完成、失败或阻塞再通知 manager 决策；单项目单 manager 可同时管理多条独立管线。每条链仍顺序执行，不增加通用依赖图需求。

代码汇总到本次需求的交付分支，由用户决定何时合入原工作分支；集成仍由 manager 委派的 worker 执行。

实现、集成、冲突处理仍交给 worker。manager 可查看代码和结果，不直接承担实现、验收执行或合并。

## 影响

- 中央服务需能表达管线及阶段关系，不能只记录不相关的 worker 进程。
- 需要区分实现阶段完成、验收阶段通过和集成完成。
- 每个 worker 的独立 worktree 决定了验收阶段必须获得待验收实现的明确版本；提交或其他产物交接方式尚未设计。
- 自动恢复需要覆盖管线进度和待处理的阶段完成消息。
- 用户对 worker 的直接消息、暂停、取消和重试需要同步给 manager，并考虑对后续阶段的影响；具体规则待确定。
- 委派验收可减少 manager 执行长测试的占用；用户可用普通发送等待处理，也可主动选择立即打断。各 CLI 的实际中断和会话继续能力需要验证。

## 待确认

- 验收标准、证据格式、阶段产物交接、集成后复验、返工上限的记录与达到上限后的行为。
- 用户立即打断时在途工具调用和消息的处理方式，以及 worker 默认继续运行的具体语义。
