# 0.1.77：原 TUI 内容与布局还原

用户选择 A 的墨黑视觉；内容、布局和键盘操作以原 TUI 为准。0.1.74–0.1.76 的独立 Webview 设计未满足此要求，旧记录中的“已还原”结论不成立。

| 部分 | 旧版偏差 | 本轮实现与证据 |
| --- | --- | --- |
| 标题与导航 | 品牌、Manager/Workers 按钮、项目、Ready 和计数拆成不同区域 | 直接使用 `TerminalUI.headerLines`，移除独立标签按钮；相同列数下逐字对照 |
| 项目 | 用 basename 显示 `SA`，丢失完整路径与项目代码 | 原项目行、完整路径、三行窗口、Alt+↑↓、`-B` 路由；切换清空旧项目浏览器历史缓存 |
| Manager | 欢迎文案、活动卡片、用户右侧气泡，缺少消息元数据 | 沿用原可见事件过滤、角色/序号/时间、Markdown、独立边框；空会话保持空白 |
| Workers | 独立工具栏与内容切换按钮 | 原列表/详情、焦点提示、元数据和备注；F2–F6、←→、`/open`、`/diff` |
| 审批、问题、队列 | 卡片与额外操作按钮 | 原文本行、ID、slash 指令与队列内容；原 `/approval`、`/question` 详情区域 |
| 输入 | 额外模型、发送、停止工具栏，独立补全逻辑 | 原共享草稿、输入历史、行内补全与原命令控制器；Enter 提交、Shift+Enter 换行；发送期间可继续编辑 |
| 设置、帮助 | 模态弹层、独立字段与文案 | 原页面内容、字段顺序、默认值、验证和键盘保存流程 |
| 滚动与更新 | DOM 重建影响选择和展开 | 原滚动状态语义，原生滚动；按消息键复用 DOM，保留选区和工具展开 |
| 工具详情 | 展开正文未经过 Markdown，与 TUI 的缩进、文件/复制链接不一致 | 抽出共用 `conversationPresentation`，折叠/展开的标题、完整正文逐字核对；实际点击文件和代码复制链接 |
| 键盘与尺寸变化 | Worker 选中项可能移出视口；宽窄切换时用旧布局测宽；Shift+Enter 和 Tab 行为有偏差 | 选择自动滚入视口；先排版再测宽；长消息保留角色标签；Tab 保持输入焦点，Shift+Enter 插入换行 |
| 附件 | 原 TUI 宿主已提供图片按钮和预览 | 保留宿主已有入口，核对添加、移除和下一条消息携带；非新增导航 |

原控制器通过 `vscode-extension/ui-runtime.cjs` 静态打包到 Webview，去除 Node 终端传输方法；不使用 eval、xterm 或终端帧 IPC。原 `frame()` 仅在本地计算布局行数和页脚，返回的帧字符串不会画到 DOM。

另修复原 TUI 的换行缺陷：`labeledLines` 曾把整个前缀当作单个字符测宽，导致窄栏状态和提示丢字；现在按字符累加宽度，并有回归测试。

验证入口：

```powershell
npm.cmd test
npm.cmd run check
node scripts/verify-webview.mjs
node scripts/render-tui-comparison.mjs
```

浏览器核对使用独立 Node `TerminalUI` 作为参考，相同数据/列数逐字比较标题、项目、状态、提示、消息标签与正文、Worker 详情、请求、队列、设置与页脚；实际 CDP 键盘事件验证命令和导航。证据页：[A / TUI 布局核对](../design/style-samples/index.html)。完整截图与 TUI 文本在 `.tmp/webview-review`。

当前证据：149 项测试、代码检查通过；57 个浏览器内容对照及键盘/链接/滚动检查通过。折叠与展开的工具正文也纳入全部场景对照，不再只检查普通消息。
